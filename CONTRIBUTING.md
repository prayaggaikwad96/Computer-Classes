# Contributing

Thank you for helping improve this computer-science learning archive.

## Before making changes

1. Start from the latest `main` branch and create a focused topic branch.
2. Keep each change small, descriptive, and easy to review.
3. Preserve existing notes, exercises, and directory structure unless a change is necessary.
4. Add source references where they help readers verify technical claims.
5. Never commit passwords, API keys, tokens, private records, real `.env` files, generated caches, or local build output.
6. Do not force-push shared branches or remove recovery/history branches as part of routine cleanup.

## Learning material quality

- Use clear headings and descriptive filenames.
- Include prerequisites and commands for examples that require tools or dependencies.
- Mark version-specific behavior and distinguish verified facts from personal notes.
- Keep code examples minimal, reproducible, and safe to run.
- Do not copy third-party material without permission; retain applicable license and attribution notices.

## Reviewing a change

Before submitting a pull request, inspect the rendered Markdown, verify links, and run any checks relevant to changed examples. Explain the motivation, what changed, how it was checked, and any known limitations.
